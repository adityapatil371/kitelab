# Merge design — 2026-10-01

Read-only design over the current checkout. No pipeline, test, cache, or research rerun was performed for this document. ## Fixed rules for the eventual builds

* CAGR is `100 * ((end/start) ** (365.25 / elapsed_calendar_days) - 1)`, with strictly positive start/end and dates of the first and last observations being annualised. A zero/negative balance or zero span needs an explicit missing-result policy (Decision 5). A refactor may retain existing account *span endpoints* until its number-changing convention job, but may not introduce `len(returns)/252` as CAGR.
* **Buy and hold** buys fixed shares once at each included name's entry and never rebalances. `EW daily` is the name for the daily rebalanced equal-weight series in `scripts/waterfall.py` rung F; its account model also equal-weights daily. Do not relabel that series as buy and hold. A fixed-share hold comparison is a distinct benchmark, not a replacement of rung F.
* In a refactor-only build, capture old outputs before editing; compare trade dictionaries including timestamps, quotes, fills, fees, stop reasons, and shares, with deterministic seed and fixed symbols/dates. Convention jobs then compare against both the frozen old result and a hand-calculated oracle, and document every changed field.

## DECISIONS for owner

1. **Volatility annualisation.** Current: `kitelab/curves.py:85–155`, `scripts/pbo.py:~180–190`, `scripts/wf_daily.py:79,~350` use 252 for risk statistics; waterfall used 252 for CAGR, which the fixed rule supersedes. Options: 252 observed trading sessions; actual observations per calendar year; calendar-time weighted irregular returns. **Recommend 252 for Sharpe/Sortino/HAC comparability, labelled “trading-session annualised”; use elapsed days only for CAGR.**
2. **Drawdown definition.** Current: `waterfall.py:~278` starts a return curve at the first compounded return and `cummax`s it; `curves.py:53–64` uses first close; `portfolio.py:~297–380` marks daily account equity including cash; `validation.py:~853–875` includes initial capital in bootstrap paths; `n500_profile.py:74–80` uses per-stock close peaks. Options: include initial capital/wealth=1 as a peak, or start at first observed post-return value; close-only or full account/cash-marked. **Recommend initial capital as peak and daily marked account wealth for accounts; label price-only drawdown separately.** A first-day −10% return then measures −10%, versus 0% if that day becomes the initial peak.
3. **Late-listed names in fixed-share basket.** Current: `validation.py:175–245` and `wf_daily.py:132–166` reserve Rs1/name as zero-return cash until each first close; `wf_survivor.py:164–166` normalizes similarly; `waterfall.py:340–344` EW daily invests only in available returns. Options: reserve each slot in cash; invest only in names present on start date; allocate late cash across existing names. **Recommend reserve cash, then buy once at first eligible close**, retaining the board's current comparator; publish eligibility and first/last span. Clarify whether `MIN_HOLD_BARS` exclusions are decided ex ante.
4. **Cash return.** Current: `validation._hold`/`wf_daily.hold_curve` use 0% on reserved pre-listing cash; `portfolio.py` cash is nominal; waterfall EW daily excludes unavailable names via `mean(skipna=True)`. Options: zero; dated risk-free series; separate cash and invested returns. **Recommend zero nominal cash return, with a separate sensitivity run if needed.**
5. **`ddof` and undefined metrics.** Current: `wf_daily.py:356` and `validation.py:~819,1193` use `ddof=1`; pandas `.std()` in `validation.py:~528` defaults to 1; `indicators.py:97` explicitly uses `ddof=0` for Bollinger bands; `curves.py:~116–155` has its own daily-return stdev; `waterfall.py` uses pandas operations and 0/−100 sentinels in places while `portfolio.py` returns `None` when CAGR cannot exist. Options: sample `ddof=1` for inferential/research dispersion and population `ddof=0` for complete-path descriptive volatility; one global ddof; `None` versus sentinel on invalid growth. **Recommend contextual ddof as above, preserve Bollinger 0, and `None`/NaN for undefined CAGR with explicit formatting at output boundaries.**
6. **Spread on timeframe trades.** Current: `backtest.py:~420–486`, `darvas.py:~230–294`, `holygrail.py:~410–445` use `slippage.fill`; `timeframes.py:~279–322` does not. Options: preserve quoted-only timeframe numbers; apply the same spread and richer trade fields; report both fills. **Recommend matching the spread model for comparable board rows, as a separate convention build after M1 parity.** This will lower affected net returns and alter cache-dependent dashboard cells.

## Owner decisions, 2026-10-01

All six decisions are accepted as recommended:

1. Use 252 for volatility and Sharpe/Sortino/HAC risk statistics only, labelled “trading-session annualised”. Compute CAGR from elapsed calendar days divided by 365.25.
2. Include initial capital as a drawdown peak. Mark account equity daily, including cash; label price-only drawdown separately.
3. Hold late-listed names' allocation as cash until the first eligible close, then buy once.
4. Use zero nominal cash return.
5. Use `ddof=1` for inferential/research dispersion and `ddof=0` for Bollinger bands and complete-path descriptive volatility. Represent undefined CAGR as `None`/NaN, without 0 or −100 sentinels.
6. Apply the `slippage.fill` spread to `timeframes.py` trades in a separate convention build after M1 parity.

The build order above remains in force.
